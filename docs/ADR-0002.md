# ADR-0002: Named Pipe Native PowerShell Engine

**Date:** 2026-07-29

## Status
Accepted

## Context
Running Windows OS tweaks typically requires PowerShell scripts. Dropping `.ps1` files to disk and executing them is a common approach but carries significant drawbacks:
- It creates disk I/O overhead.
- Dropped scripts are frequently flagged by Antivirus (AV) and AMSI (Antimalware Scan Interface) as suspicious, causing false positives and blocking execution.
- Managing cleanup of temporary scripts adds complexity.

## Decision
We implemented a **Named Pipe Native PowerShell Engine** that utilizes in-memory Base64/stdin streams to execute PowerShell scripts. 

- Scripts are encoded in Base64 within the Node.js main process.
- Execution is triggered via `stdin` or named pipes to `powershell.exe`.
- No `.ps1` files are ever dropped to the disk.

## Consequences
**Positive:**
- **Zero Disk Latency:** Operations start up immediately in memory.
- **AMSI/AV Bypass by Design:** Since there are no files dropped, heuristic file scanners do not flag the optimization executions.
- **Cleaner Execution:** No temporary files to manage or clean up.

**Negative:**
- **Debugging Complexity:** Debugging failed scripts requires inspecting the memory or logging standard error streams instead of just opening a `.ps1` file.
- **Payload Limits:** While Base64 payload limits via command-line arguments are generally large enough for our tweaks, extremely large scripts might require chunking or pure stdin streams.
